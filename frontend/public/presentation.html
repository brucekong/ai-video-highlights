Problem Fit

它解决的，不只是“看视频太慢”

真正的问题是长视频的信息密度高，但消费路径是割裂的。用户得在播放器、字幕、笔记软件、 搜索框和剪辑工具之间反复切换，结果是知道内容有价值，却很难快速吸收、引用和复用。

Why This Matters

信息获取的断裂

  • 长视频通常只能顺序播放，无法像文档一样直接定位到某个知识点。
  • 字幕和摘要是分离的，用户难以判断“这一段为什么重要”。
  • 外语视频的价值常常卡在听力门槛，不能稳定沉淀为中文知识材料。

内容复用的断裂

  • 看完视频以后，知识点无法自然进入 Notion、Obsidian 或二创流程。
  • 剪视频的人需要重新找时间点、重写脚本、重复整理摘要。
  • 历史分析结果缺少统一检索入口，之前处理过的视频价值会被再次埋没。

目标不是“帮用户看完视频”，而是把视频重构成一个可交互的知识界面。

从播放器时代进入知识工作台时代，才是这个项目现在更准确的定位。

Workflow

当前版本的真实使用路径

从提交链接，到先展示视频与字幕，再异步补全 AI 摘要、脑图、翻译和索引， 最后进入搜索、问答、导出和剪辑的复用阶段。

01

提交视频

支持 YouTube 链接。首页除了分析入口，也提供全库语义搜索入口。

02

先可看，再补全

视频页优先把播放器和字幕展示出来，减少等待成本，AI 结果在后台逐步补全。

03

进入交互

摘要可定位时间点，字幕可双语浏览与编辑，脑图可展开，视频内搜索和 AI 对话可继续深挖内容。

04

产出资产

导出 Markdown / Notion，生成剪辑脚本，打开片段剪辑抽屉，让分析结果直接进入复用链路。

Capability Matrix

它已经具备的能力矩阵

如果按用户任务拆分，它已经覆盖了“发现内容、理解内容、修正内容、复用内容”四个阶段。

Discover to Reuse

发现内容

Discover
  • 首页全库语义搜索，支持自然语言描述命中历史分析结果。
  • 视频页内搜索，帮助用户快速锁定单个视频中的目标内容。
  • 历史记录抽屉保留标题、标签、分类和摘要数量，降低二次进入成本。

理解内容

Understand
  • AI 自动生成 takeaways、脑图、标签、分类、视频描述与 hashtags。
  • 字幕支持双语展示，英语视频可以逐步补齐中文翻译。
  • AI 对话流式返回，围绕当前视频上下文继续深挖问题。

修正内容

Refine
  • 字幕支持手动编辑，避免自动切分和翻译结果影响最终可读性。
  • 支持重建 subtitle cues，让字幕分段规则可以迭代优化。
  • 关键词词表支持补充与维护，让学习型视频的知识点更可沉淀。

复用内容

Reuse
  • 支持导出 Markdown、Notion 与脑图，分析结果可以进入知识库。
  • 自动生成剪辑脚本，并提供片段剪辑抽屉，把 takeaways 直接转成素材。
  • 内容不再只停留在播放器里，而是继续服务于学习、写作和二次创作。
Engineering

工程上，它已经具备产品化雏形

前后端边界已经比较清晰，服务端也有 API 文档、 数据模型与多条业务路由，为后续继续扩展留下了比较好的空间。

Product Foundation
Frontend

Vue 3 工作台式前端

  • 首页负责分析与搜索双入口，视频页负责高密度交互工作台。
  • 播放器、脑图、搜索弹窗、历史抽屉、字幕编辑、剪辑抽屉都已组件化。
  • Vite + TypeScript 让页面迭代速度和可维护性保持在舒适区间。
Backend

Fastify 服务与结构化 API

  • 分析、聊天、搜索、视频详情、转录等路由已拆开，边界清晰。
  • 集成 OpenAPI / Scalar 文档，接口已经进入可被外部理解和维护的阶段。
  • 支持认证、跨域、健康检查，具备基本线上服务意识。
Data

Prisma 数据层承接沉淀

  • 视频、takeaways、chat、subtitles、subtitle cues 等数据都已有模型支撑。
  • 历史记录和搜索并不是临时内存态，而是在往长期积累方向走。
  • 这意味着“分析一次，多次复用”的产品逻辑成立。
AI Layer

AI 不只做摘要，还承担索引与交互

  • DeepSeek 负责摘要、脑图、翻译、问答等核心分析任务。
  • 语义搜索侧引入 embedding 能力，把历史内容变成可检索资产。
  • 设计上优先“先展示可用内容，再补全 AI 结果”，体验比一次性阻塞更成熟。
Vibe Coding

关于 vibe coding，我更在意的不是“快”，而是“把人放回创造的中心”

AI 让原型、交互和功能拼装的门槛大幅下降， 但真正决定产出质量的，依然是你有没有清晰的问题意识、判断力和审美。

Human + AI

vibe coding 真正擅长的事

  • 快速把模糊想法变成一个可看、可点、可验证的产品雏形。
  • 降低尝试成本，让开发者更敢于探索交互、流程和表达方式。
  • 把很多原来“懒得做”的小优化，变成可以顺手实现的事情。

但它不能替代的能力

  • 你得知道什么问题值得解决，什么功能只是“看起来很炫”。
  • 你得能判断生成结果是否靠谱，是否真正提升了用户体验。
  • 你得对产品气质负责，因为 AI 只能放大方向，不能替你定义方向。

代码正在变得更便宜，
但好问题、好判断和好审美，反而变得更贵。

所以我理解的 vibe coding，不是“让 AI 替我做产品”，而是“让我把更多精力放回真正值得做的决定”。
